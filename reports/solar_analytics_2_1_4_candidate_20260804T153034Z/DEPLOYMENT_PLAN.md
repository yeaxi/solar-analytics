## Rollback gate

Stop and restore the pre-change component/database/configuration backup if any of the following occurs:

- `ha core check` fails before or after promotion;
- readiness does not recover;
- config entry migration does not reach version `4` or loses unrelated/native metadata;
- native entry ID changes;
- REST producer returns or native-only references are altered;
- new Solar Analytics/Forecast.Solar traceback, unload failure, or duplicate-listener error appears;
- SQLite integrity fails or v2/backfill lineage is changed unexpectedly;
- physical service calls or notifications are non-zero unexpectedly.

Rollback itself requires the same explicit activation approval: restore the old component atomically, run `ha core check`, restart once, poll readiness, and perform read-only state/log/storage readback. Do not delete Recorder rows or hand-edit `.storage` as an expedient rollback.
